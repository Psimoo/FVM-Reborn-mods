# 延迟创建对象池方案

## 方案目标

本方案采用“第一次使用时创建，后续重复复用，每局结束清空”的对象池生命周期：

- 游戏开始时不提前创建子弹；
- 第一发某类型子弹发射时，先创建并登记对象池；
- 后续相同类型子弹优先从池中取出；
- 某类敌人第一次出现时，创建并登记该类敌人池；
- 敌人死亡后回收到池中，后续同类敌人复用；
- 对局结束时清空本局所有对象池；
- 下一局重新建立新的对象池。

这种方式不会产生启动阶段的预加载开销，也不会为本局没有使用的子弹或敌人分配实例。第一次使用某类型对象时仍可能有一次创建成本，因此需要重点测试第一发子弹和第一只敌人出现时是否产生明显瞬时卡顿。

## 生命周期

```text
对象池不存在
    |
    | 第一次发射子弹 / 第一次生成敌人
    v
按对象类型创建池并创建第一个实例
    |
    v
对象进入场内
    |
    | 命中、出界、死亡或暂时离场
    v
对象回收到对应池
    |
    | 下一次发射或生成
    v
从池中取出并重置后重新进入场内
    |
    | 对局结束
    v
释放池中全部实例和数据结构
```

## 与预加载方案的区别

| 项目 | 延迟创建对象池 | 预加载对象池 |
|---|---|---|
| 游戏开始内存占用 | 较低 | 较高 |
| 游戏开始耗时 | 较低 | 可能增加 |
| 第一发对象开销 | 仍有创建成本 | 通常较低 |
| 未使用对象类型 | 不创建 | 可能已经创建 |
| 局间清理 | 每局结束清空 | 每局可复用或清空 |
| 适合当前需求 | 是 | 否 |

当前需求应使用延迟创建，不调用战斗开始阶段的 `obj_pool_prealloc`。

## 池数据结构

对象池应按对象类型分开保存。建议使用对象索引的字符串作为键：

```gml
global._obj_pools = ds_map_create();
```

每个键对应一个池记录：

```gml
{
    object_index: obj_coffeecup_bullet,
    instances: ds_list_create(),
    active_count: 0,
    peak_count: 0,
    created_count: 0
}
```

如果项目继续使用现有 `ds_map -> ds_list` 结构，也必须保证每局只初始化一次，并在对局结束时销毁全部 `ds_list` 和实例。

## 第一次发射子弹

第一次发射某类子弹时，池中没有可复用实例，流程应为：

1. 根据对象索引查找池；
2. 如果池不存在，创建该类型的池记录；
3. 从池中查找可用实例；
4. 如果池为空，创建一个新实例；
5. 将实例初始化为本次发射状态；
6. 标记为场内活动对象。

推荐接口：

```gml
function pool_acquire_bullet(_obj, _x, _y, _depth) {
    var _pool = pool_get_or_create(_obj);
    var _inst = pool_take_idle(_pool);

    if (_inst == noone) {
        _inst = instance_create_depth_origfunc(_x, _y, _depth, _obj);
        _inst.pool_created_this_round = true;
        _pool.created_count += 1;
    }

    _inst.x = _x;
    _inst.y = _y;
    _inst.depth = _depth;
    _inst.active = true;
    _inst.pooled = false;
    _inst.visible = true;
    _inst.pool_generation += 1;
    _pool.active_count += 1;
    _pool.peak_count = max(_pool.peak_count, _pool.active_count);

    return _inst;
}
```

实际代码需要根据现有 `obj_pool.gml` 的数据结构调整。核心要求是：池不存在时自动创建，池为空时允许动态创建，不能因为池容量暂时不足而丢失子弹。

## 后续子弹发射

子弹回收后保留实例，不执行销毁。下一次发射从池中取出，并完整重置：

```gml
var bullet = pool_acquire_bullet(obj_coffeecup_bullet, start_x, start_y, depth);

with (bullet) {
    damage = source_damage;
    damage_type = source_damage_type;
    move_speed = source_speed;
    row = source_row;
    target_type = source_target_type;
    life_timer = 0;
    image_index = 0;
    image_alpha = 1;
    image_angle = source_angle;
    hitted_enemy = [];
}
```

不得只恢复位置和可见性。旧的目标、穿透记录、计时器、角度和动画状态都可能影响下一次发射。

## 子弹回收

命中、越界、撞击障碍物或生命周期结束时调用统一接口：

```gml
pool_release_bullet(id, "hit");
exit;
```

回收逻辑应满足：

```gml
function pool_release_bullet(_inst, _reason) {
    if (!instance_exists(_inst)) return;
    if (_inst.pooled) return;

    var _pool = pool_get_or_create(_inst.object_index);

    with (_inst) {
        active = false;
        pooled = true;
        visible = false;
        x = -10000;
        y = -10000;
        speed = 0;
        hspeed = 0;
        vspeed = 0;
        image_index = 0;
        image_alpha = 1;
        image_angle = 0;
        life_timer = 0;
        damage = 0;
        target = noone;
        hitted_enemy = [];
    }

    ds_list_add(_pool.instances, _inst);
    _pool.active_count = max(0, _pool.active_count - 1);
}
```

所有子弹对象都必须把原来的 `instance_destroy()` 替换为统一回收接口，否则对象池无法降低创建和销毁次数。

## 池内对象必须停止逻辑

池内对象不能继续执行 Step、碰撞和音效。每个池化子弹的 Step 开头应加入：

```gml
if (!active || pooled) exit;
```

如果对象有 Collision 事件，也要增加相同保护：

```gml
if (!active || pooled) exit;
```

如果使用 `instance_deactivate_object`，回收时停用实例，取出时重新激活实例。但要确认对象池管理器没有被包含在停用范围内。

## 第一次生成敌人

敌人不在战斗开始时预创建。某类敌人第一次生成时：

1. 根据敌人对象索引查找池；
2. 池不存在时创建池记录；
3. 从池中查找闲置实例；
4. 池为空时创建第一个敌人实例；
5. 写入本波次的敌人数据；
6. 重置生命、状态、目标和动画；
7. 注册到 `global.enemy_by_type`；
8. 放入场内。

推荐接口：

```gml
var enemy = pool_acquire_enemy(enemy_obj, spawn_x, spawn_y, depth);
pool_reset_enemy(enemy, enemy_data);
enemy.active = true;
enemy.visible = true;
pool_register_enemy(enemy);
```

`Create` 事件只会在实例第一次创建时执行。后续从池中复用时不会再次执行 Create，因此所有复用状态必须放到显式的 `pool_reset_enemy` 中。

## 敌人复用时必须重置

至少重置以下字段：

```gml
active = true;
pooled = false;
visible = true;
state = ENEMY_STATE.NORMAL;
hp = maxhp;
target_plant = noone;

ice_timer = 0;
frozen_timer = 0;
stun_timer = 0;
scare_timer = 0;
flash_value = 0;
is_frozen = false;
is_slowdown = false;
is_stun = false;
is_scare = false;

shield_hp = shield_max_hp;
helmet_hp = helmet_max_hp;
image_alpha = 1;
image_index = 0;
timer = 0;
attack_timer = 0;
enemy_registered = false;
target_type = enemy_data.target_type;
```

还要清理上一个敌人留下的附属对象、绑定特效、死亡标记、出生坐标和特殊技能计时器。实际字段需要逐个对照各敌人对象的 Create、Step、Destroy 和 User Event。

## 敌人类型索引

当前子弹通过 `global.enemy_by_type` 查找可命中的敌人。敌人回收到池内时必须先注销：

```gml
pool_unregister_enemy(id);
```

敌人重新进入场内时再注册：

```gml
pool_register_enemy(id);
```

如果不注销，类型数组中会保留同一个敌人的旧 ID；如果不重新注册，子弹会找不到复用后的敌人。注册和注销都必须检查 `instance_exists`，并避免同一实例重复加入数组。

## 敌人死亡与回收

敌人死亡不能立即等同于对象销毁。建议流程：

```text
hp <= 0
    |
    v
只执行一次死亡结算和掉落
    |
    v
播放死亡动画或隐藏
    |
    v
注销 enemy_by_type
    |
    v
清理状态并加入敌人池
```

现有 `objects/obj_enemy_parent/Destroy_0.gml` 包含类型注销和随机掉落。池化回收时如果直接调用普通 `instance_destroy()`，可能造成重复掉落、重复音效或错误的战斗结算。

建议增加区分标志：

```gml
pool_cleanup = false;
death_reward_processed = false;
```

正常死亡时：

```gml
if (!death_reward_processed) {
    death_reward_processed = true;
    enemy_drop_reward();
}

pool_release_enemy(id, "death");
```

对局结束清空池时，不应再次执行死亡奖励。

## 每局结束清空对象池

每一局游戏结束时统一调用：

```gml
pool_clear_round();
```

清空顺序建议如下：

1. 设置 `global.pool_shutting_down = true`；
2. 停止发射、敌人生成和战斗计时；
3. 注销所有敌人类型索引；
4. 清理池内和场内的池化实例；
5. 销毁每个池对应的 `ds_list`；
6. 销毁全局池 `ds_map`；
7. 重置池初始化标志；
8. 设置 `global.pool_shutting_down = false`。

示例：

```gml
function pool_clear_round() {
    global.pool_shutting_down = true;

    if (variable_global_exists("_obj_pools")
        && ds_exists(global._obj_pools, ds_type_map)) {
        var keys = ds_map_keys_to_array(global._obj_pools);

        for (var i = 0; i < array_length(keys); i++) {
            var pool = ds_map_find_value(global._obj_pools, keys[i]);
            if (!ds_exists(pool, ds_type_list)) continue;

            for (var j = 0; j < ds_list_size(pool); j++) {
                var inst = ds_list_find_value(pool, j);
                if (instance_exists(inst)) {
                    inst.pool_cleanup = true;
                    instance_destroy(inst);
                }
            }

            ds_list_destroy(pool);
        }

        ds_map_destroy(global._obj_pools);
    }

    global._obj_pools = noone;
    global._obj_pool_initialized = false;
    global.pool_shutting_down = false;
}
```

实际清理函数还应处理当前仍在场内的池化实例。不能只清理池列表，因为场内活动对象不在闲置列表中。

## 对局结束触发点

清空对象池应接在统一的对局结束流程中，例如胜利、失败、退出战斗和切换房间。建议不要只在某一个 `game_over` 对象的 Destroy 事件中清理，因为直接退出房间、重新开始或异常切换也可能绕过该事件。

可以由战斗管理器统一调用：

```gml
if (battle_is_finished) {
    pool_clear_round();
}
```

清理函数应保证重复调用安全。即使同一局触发两次，也不能重复销毁 `ds_list` 或访问已经清理的实例。

## 动态扩容

池为空时允许按需创建：

```text
第一次使用类型 A：创建池，创建实例 1
同时存在达到 10 个：动态创建实例 2 到 10
实例回收：加入池
后续使用：从池中取出复用
```

这样可以避免预加载，同时把创建开销分散到真正需要对象的时刻。为了减少高峰期间连续扩容，可以在检测到连续扩容时一次增加少量备用实例，例如 4 个，但这仍属于按需扩容，不是开局预加载。

## 对象池与碰撞优化的关系

对象池减少实例创建和销毁，不能直接减少子弹碰撞计算。建议同时采用：

1. 同行判断；
2. x 轴距离粗筛；
3. 简单矩形粗筛；
4. 最后调用 `precise_bbox_collision`。

如果碰撞每 2 帧执行一次，必须保存上一帧位置并检查运动线段，否则高速子弹可能穿透敌人。移动可以每帧执行，碰撞候选检查可以按频率降低。

## 统计指标

实施前后使用同一关卡、同一波次和同一卡组比较：

- 平均 FPS；
- 1% 最低 FPS；
- 单帧最长耗时；
- 每秒新建实例数量；
- 每秒销毁实例数量；
- 当前池数量；
- 每种对象池的创建峰值；
- 当前活跃子弹和敌人数量；
- 子弹命中数量和 DPS；
- 敌人掉落数量；
- 第一发子弹和第一只敌人出现时的单帧耗时；
- 对局结束后剩余实例和数据结构数量。

第一发子弹或第一只敌人出现时出现一次轻微峰值是延迟创建的正常代价。如果峰值明显影响操作，可以对“即将使用的单个类型”提前在发射前一帧创建，但这仍然属于局部延迟创建，不是全局预加载。

## 实施顺序

1. 改造一个普通子弹的发射、回收和复用流程；
2. 验证池内对象不执行 Step、Draw 和碰撞；
3. 记录第一发子弹的创建耗时；
4. 扩展到爆炸和命中特效；
5. 改造一个普通敌人的首次生成、死亡、注销和复用；
6. 验证掉落、血量、状态和类型索引；
7. 将 `pool_clear_round` 接入胜利、失败、退出和换房间流程；
8. 最后扩展到其他普通敌人；
9. 暂时保留 Boss 和复杂附属对象的普通生命周期。

## 验收标准

方案完成后应满足：

- 游戏开始时没有创建未使用的子弹或敌人实例；
- 某类型对象第一次使用时自动创建对应对象池；
- 对象回收后可以再次取出并正确重置；
- 池内对象不执行移动、碰撞、音效和绘制；
- 敌人不会重复掉落奖励；
- `global.enemy_by_type` 不包含池内敌人；
- 子弹可以命中复用后的敌人；
- 高速子弹没有新增明显穿透；
- 每局结束后池、实例、`ds_list` 和 `ds_map` 都被清理；
- 下一局不会继承上一局的子弹、敌人、伤害或状态。

## 结论

“第一次使用时写入对象池，之后复用，对局结束清空”适合当前需求。它减少了开局内存和预加载时间，同时保留对象池对高频创建销毁的优化效果。实现重点是延迟创建、完整重置、池内停用、敌人索引维护和每局统一清理。
