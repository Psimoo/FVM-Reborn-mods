# 新金卡逻辑检查报告

## 检查范围

本报告基于当前仓库中卡片对象、卡牌注册表和卡片说明进行静态检查。当前环境未运行 GameMaker 编译器，也未进入游戏实测，因此结论针对代码逻辑，不能代替运行时验证。

## 已发现问题

### 1. 神农竖弹列命中计数没有生效

位置：`objects/obj_shennong_god_bullet_v/Step_0.gml`，约第 83–109 行。

每列第一次命中时使用 `ds_map_replace` 写入计数，但该键尚未创建时 replace 不会新增键，计数继续为 0。因此中心列两次命中的限制不会生效，其他列也无法可靠限制为一次。与此同时，`hitted_enemy` 记录敌人 ID，阻止同一只敌人再次受击，所以“第 8 列受击 2 次”也无法按每只敌人实现。

建议先明确设计语义：如果每只鼠在中列应受击两次，应按“敌人 ID + 列/命中阶段”记录；如果限制的是每列总命中数，则按列创建计数键并检查计数。验收时分别放置中列一只高血量鼠、同列多只鼠、两侧列多只鼠，确认伤害次数。

### 2. 光明神每次攻击只造成一次伤害

位置：`objects/obj_guangming_god/Step_0.gml`，约第 143–177 行。

卡片说明写每次攻击持续 2.1 秒、造成 10 次伤害；当前 `has_fired` 触发时只遍历目标一次，并对每只目标调用一次伤害事件，没有 10 次伤害的计时逻辑。表现会变成一次爆发，而不是持续多段伤害。

建议将一次攻击拆为明确的攻击状态计时：启动时锁定或动态选择目标，2.1 秒期间每隔固定帧数结算一跳，共 10 跳；结束后清理状态。测试需覆盖目标中途死亡、离开范围、暂停、卡片被铲除等情况，避免漏结算或重复结算。

### 3. 重生卡片在 Create 事件之后才恢复形态和等级

位置：`objects/obj_chongsheng_god/Step_0.gml`，约第 59–63 行。

`instance_create_depth` 会先执行卡片自己的 Create 事件，代码随后才设置 `current_level`、`skill`、`shape` 并调用用户事件。Create 中基于形态设置的精灵、范围、`plant_type` 或其他专属变量，可能已经按默认形态初始化。尤其是悬浮卡或高转卡，复活后可能显示或占格行为不正确。

建议改成创建前可传入初始化数据的统一卡片创建流程，或在恢复字段后调用专门的“按当前形态重建状态”函数，并确保清理旧状态后重算。验收时分别复活基础、三转、终转及悬浮卡，核对精灵、等级属性、格子占用、技能和攻击行为。

### 4. 重生神终转的复活数量配置前后不一致

对象运行上限在 `objects/obj_chongsheng_god/Create_0.gml` 约第 36–39 行设为 9；`scripts/mod_slots_init/mod_slots_init.gml` 约第 2803–2807 行的终转说明则写 12 张。

请确认最终设计值。若应为 9，修改卡牌说明；若应为 12，修改运行逻辑并检查其余说明/信息岛文案。测试终转范围内超过上限数量的死亡记录，确认只复活预期数量。

### 5. 重生神减伤 Buff 计时器每帧续期

位置：`objects/obj_chongsheng_god/Step_0.gml`，约第 88–104 行；计时递减在 `objects/obj_card_parent/Step_0.gml` 约第 19–25 行。

只要 `buff_applied` 为真，重生神每帧都会将范围内卡片的 `chongsheng_buff_timer` 重置为 `buff_duration`。因此 Buff 不会自然到期，只会在重生神离场或离开范围后开始倒计时。这与“持续时间”配置的通常含义不一致。

建议只在施加/刷新 Buff 的时机写入计时器，而不是每帧施加；同时明确它是一次性限时 Buff、周期刷新 Buff，还是光环常驻效果。分别测试离场、铲除、多个重生神覆盖和计时结束。
